# 引入活跃班次判定逻辑并增强 syncWidget() 决策

_来源：e7fa8b2 → d09a0a9 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
小组件需要根据当前时间动态判断是否显示打卡按钮，包括今天班次的正常时段、昨天跨午夜班次的延续时段，以及内置休息/调休班次的特殊规则。

## 决策驱动
- 准确判断用户当前可打卡状态
- 支持跨午夜班次的特殊情况
- 内置班次的差异化处理

## 备选方案
- **findActiveShift() 函数 + 时间归一化** — 优点：统一处理今天和昨天的班次；通过时间偏移解决跨午夜问题；300秒容差提升用户体验；缺点：逻辑相对复杂
- **简单的当前时间比较** _（已否决）_ — 优点：实现简单；缺点：无法处理跨午夜班次；没有容差机制；用户体验较差

## 决策
在 CalendarViewModel 中新增 findActiveShift() 函数，通过检查今天和昨天的排班记录，结合班次时间的归一化处理（end < start 时 end += 1440）和 -1440 分钟偏移，判断当前时间是否在有效打卡窗口内（start-300 到 end+300 秒范围）。syncWidget() 集成该判定结果和内置班次规则来确定按钮显示。

## 影响
Widget 能准确显示用户当前可执行的打卡操作，包括提前5分钟打卡和延后5分钟打卡的容错。内置休息/调休班次在无附加状态时不显示打卡按钮，有自定义状态时按规则4处理。
